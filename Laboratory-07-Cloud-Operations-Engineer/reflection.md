
# Mission Reflection
```
This laboratory activity helped me understand why monitoring is an important part of cloud computing and system administration. Checking the host server's resources is important even when containers are running perfectly because containers still depend on the physical or virtual host for CPU, memory, disk space, and other resources. If the host becomes overloaded or runs out of storage, the containers may become slow, unstable, or unavailable even if the applications inside them are working correctly. Establishing a baseline also makes it easier to identify unusual resource usage later.

If a user complains that they cannot log into a web application, the `docker logs` command can help identify what happened inside the container. The logs can show incoming requests, errors, failed operations, and other events generated by the application. By checking the logs, an engineer can determine whether the login request reached the application and whether an error occurred while processing it.

Monitoring logs and monitoring metrics are different but complementary. Logs provide detailed records of events and errors, while metrics provide numerical information about system performance. In this activity, the logs showed successful HTTP 200 requests and the HTTP 404 error, while Docker metrics showed CPU, memory, and network usage.

Large enterprise companies can monitor thousands of containers by using centralized monitoring and observability platforms such as Prometheus and Grafana. Prometheus can collect and store metrics from many systems, while Grafana can present those metrics through dashboards and visualizations. These tools allow operations teams to monitor large infrastructures from a centralized location.

My ability to troubleshoot Linux environments improved because I learned to use commands such as `free`, `df`, `top`, `docker logs`, and `docker stats` to gather actual evidence about system and application health. Instead of simply guessing when a problem occurs, I can now examine logs and performance metrics to identify possible causes and make more informed troubleshooting decisions.
```
