## Mission Overview

Laboratory Activity 7 focuses on cloud operations, observability, and monitoring. The activity involves checking the health of a Linux host, deploying a containerized Nginx web server, generating web traffic, examining application logs, and monitoring the container's resource usage.

The main purpose of the activity is to use system information, application logs, and performance metrics to determine whether a cloud environment is operating properly. The activity also provides practical experience in identifying errors and monitoring the resources used by a Docker container.

## Objectives

The objectives of this laboratory activity are to:

- Monitor the host server's CPU, memory, and disk capacity using Linux command-line tools.
- Establish a baseline of the host system before deploying the web application.
- Deploy an Nginx web server using Docker.
- Generate HTTP requests to simulate website traffic.
- Intentionally generate an HTTP 404 error for an unavailable page.
- Retrieve and examine application logs from the Docker container.
- Monitor the container's CPU, memory, and network activity in real time.
- Document system observations and monitoring results using Markdown.
- Develop basic cloud operations and troubleshooting skills.

## Monitoring Commands Executed

### Check Memory Usage

```bash
free -h
```

The command was used to check the memory resources of the host server.

### Check Root File System Storage

```bash
df -h /
```

The command was used to check the storage capacity and current disk usage of the root (`/`) file system.

### Monitor Running Processes and CPU Activity

```bash
top
```

The command was used to observe the active processes and CPU activity of the host server.

### Deploy the Nginx Web Server

```bash
docker run -d -p 8080:80 --name client-website nginx
```

This command runs the Nginx web server in the background and maps host port `8080` to container port `80`.

### Verify the Running Container

```bash
docker ps
```

This command was used to verify that the `client-website` container was running.

### Generate HTTP Requests

```bash
curl http://localhost:8080
```

The command was used to simulate a user accessing the Nginx web server.

### Generate an HTTP 404 Error

```bash
curl http://localhost:8080/hidden-admin-page
```

This command was used to request a page that does not exist and generate a `404 Not Found` response.

### View Application Logs

```bash
docker logs client-website
```

This command was used to retrieve and examine the HTTP request logs generated by the Nginx container.

### Monitor Container Metrics

```bash
docker stats
```

This command was used to monitor the real-time CPU, memory, and network usage of the running container.

## Skills Learned

Through this laboratory activity, I learned how to establish a baseline of a Linux host by checking its memory, disk storage, and running processes. I also learned how to deploy and verify a web server using a Docker container.

The activity also helped me understand how HTTP requests can be used to test a web application and how an intentional `404 Not Found` response can be identified through application logs.

Another important skill I developed was using Docker monitoring commands to observe container performance. By checking logs and resource metrics, I learned how a Cloud Operations Engineer can use actual system information to investigate application behavior and possible problems.

Overall, the activity improved my understanding of cloud operations, Docker monitoring, application troubleshooting, and technical documentation using Markdown.
