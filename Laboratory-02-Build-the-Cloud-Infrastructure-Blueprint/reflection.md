# Mission Reflection

This laboratory activity helped me understand more about cloud infrastructure because I was able to actually use a Linux server through the KillerCoda Playground. Before doing this activity, I only had a basic idea of how cloud infrastructure works. While doing the different checkpoints, I learned how the different resources of a server are checked and identified. For me, I think **compute resources** are the most important because they are responsible for processing tasks and running applications. Without CPU, CPU cores, and RAM, the system would not be able to work properly.

I also learned how Linux supports cloud computing. Linux is important because it manages the server and allows us to use different commands to check its resources and information. During the activity, I used commands to check the operating system, kernel version, CPU, CPU cores, RAM, disk space, file systems, hostname, and IP address. At first, some of the commands were unfamiliar to me, but after using them, I started to understand what each command was for.

I also realized why technical documentation is important before deploying infrastructure. It helps keep the information organized and makes it easier to understand what resources and configurations are being used. It can also help when troubleshooting problems or making changes in the future.

One of the skills I learned from this activity was using basic Linux commands such as `uname -r`, `nproc`, `free -h`, `df -h`, `hostname`, and `hostname -I`. I also learned how to document my findings using Markdown.

Lastly, I think my GitHub portfolio improved because I was able to add my laboratory outputs, documentation, cloud comparisons, infrastructure diagram, and reflection. Overall, this activity gave me more confidence in using Linux and helped me understand cloud computing in a more practical way.
